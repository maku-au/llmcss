Install

One stylesheet is the entire install, with no build step and no dependency to resolve. Add the runtime script only when you use modal, drawer, dropdown, accordion, tabs, toast, command palette, combobox, scrollspy, or split panes.

<link rel="stylesheet" href="https://llmcss.io/llmcss.css" />
<script src="https://llmcss.io/llmcss.js" defer></script>

<!-- Pin a release instead of tracking latest (served immutable): -->
<link rel="stylesheet" href="https://llmcss.io/v/0.4.0/llmcss.css" />

Classes carry no prefix as of 0.4.0: write btn, never ai-btn. Custom properties keep --ai-, data attributes keep data-ai-, and custom elements keep ai-.

Theme and skin

Theming is four attributes on <html>, never a stylesheet of your own. Dark mode is never derived from the operating system setting, so set data-ai-theme yourself.

<html lang="en"
      data-ai-theme="dark"
      data-ai-skin="obsidian"
      data-ai-accent="teal"
      data-ai-density="compact">

Theme: light, dark. Skin: obsidian, editorial, executive, fintech, enterprise. Accent: emerald, violet, rose, teal, steel, amber, composing with any skin and outranking its accent. Density: compact, spacious. Focus ring: data-ai-focus="neutral|thin|none".

Every value resolves to --ai-* custom properties, all of them listed with their per-theme values in tokens.json.

Layout and utilities

Utilities are plain names and variants are written prefix first, as in md:grid-cols-2. Container queries use cq-sm:, cq-md: and cq-lg: against the nearest ancestor carrying cq or cq-inline, which is what you want inside a sidebar or a panel that does not track the viewport.

<!-- Viewport breakpoints: one column, two at 768px, three at 1024px -->
<div class="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4">
  <div class="card"><div class="card-body"><p class="text-sm">One</p></div></div>
  <div class="card"><div class="card-body"><p class="text-sm">Two</p></div></div>
  <div class="card"><div class="card-body"><p class="text-sm">Three</p></div></div>
</div>

<!-- Container query: measures the panel, not the window -->
<section class="cq">
  <div class="grid grid-cols-1 cq-md:grid-cols-2 gap-4">
    <div class="panel"><p class="text-sm">Reflows at 600px of panel width</p></div>
    <div class="panel"><p class="text-sm">No viewport query involved</p></div>
  </div>
</section>

A variant exists for a class only when classes.json lists it in that class's variants array. If a class is not in that file, it does not exist.

Chart tokens and tones

Charts read their colour from the chart slots, and data-ai-tone is how you point an element at one. The attribute inherits, so a row, a legend item or a whole chart can be toned once.

--ai-chart-1 --ai-chart-2 --ai-chart-3 --ai-chart-4 --ai-chart-5 --ai-chart-6

Slot 1 is var(--ai-accent), so the first series follows the accent and the skin without any work from you; the other slots hold their hue across every theme.

SetResolves toUse for
data-ai-tone="1" to "6"--ai-chart-1 to --ai-chart-6One series in a chart, and the legend swatch that names it.
"accent", "success", "warning", "danger", "info", "neutral"The matching theme tokenA bar or pip that carries a status rather than a series.
--ai-tone-ink60 percent of the tone toward the text colourText and glyphs. It is the only derived value that clears 4.5:1, so it is the only one that carries type.
--ai-tone-wash12 percent of the toneThe background of a tile or a legend chip.
--ai-tone-track18 percent of the tone over --ai-surface-2The unfilled part of a meter or bar rail.
 
<div class="bar-row">
  <span>CLI</span>
  <div class="bar-track" data-ai-tone="2">
    <div class="bar-fill w-3/5" data-ai-tone="2"></div>
  </div>
  <span>5,741</span>
</div>

<!-- The legend swatch beside the number takes the same tone -->
<span class="flex items-center gap-2"><span class="pip" data-ai-tone="2"></span>CLI</span>

A tone keys data, so it goes on bar-fill, bar-track, a plain pip, donut, split-bar, metric-tile and bar-col. A card, an alert, a button, a badge and the kpi-trend indicator never take one: those already carry a meaning, and a second colour on top of it encodes nothing.

Accent and series can collide: data-ai-accent="teal" and data-ai-accent="emerald" both sit close to chart slot 2, and data-ai-accent="rose" sits close to slot 4; slot 1 is already the accent. On a page using one of those accents, skip the slot it collides with.

Motion addon

Animation classes ship in a second stylesheet so the 50KB core budget never has to pay for them. Load it after the core sheet; every component keeps animating the way it already does today without it.

<link rel="stylesheet" href="https://llmcss.io/llmcss.css" />
<link rel="stylesheet" href="https://llmcss.io/llmcss-motion.css" />

<!-- Pin a release instead of tracking latest (served immutable): -->
<link rel="stylesheet" href="https://llmcss.io/v/0.4.0/llmcss-motion.css" />

Motion is evidence that something changed, never a decoration on a steady state. There is no animate-pulse, no repeat-infinite, no parallax scroll effect and no glow or drop shadow pulse: the audit's Law 2 already bans the look, and the addon does not ship the mechanism to build it.

Entrances and exits

Fourteen one-shot animate-* classes, tuned with the same duration-*, delay-* and ease-* words that already tune a transition, plus once for a single iteration and repeat-2 or repeat-3 for a bounded replay. There is no repeat-infinite.

<div class="grid grid-cols-2 md:grid-cols-3 gap-3">
  <div class="panel p-4 animate-fade-in">
    <p class="text-sm">animate-fade-in</p>
  </div>
  <div class="panel p-4 animate-slide-up duration-slow ease-overshoot">
    <p class="text-sm">animate-slide-up duration-slow ease-overshoot</p>
  </div>
  <div class="panel p-4 animate-scale-in delay-150">
    <p class="text-sm">animate-scale-in delay-150</p>
  </div>
  <div class="panel p-4 animate-rise once">
    <p class="text-sm">animate-rise once</p>
  </div>
</div>

<button class="btn btn-outline animate-nudge repeat-2">Try again</button>

Staggered children

Put stagger on the parent and animate-rise on each child; the delay comes from child position, capped at the twelfth child so a long list never arrives a second late. stagger-fast and stagger-slow change the step.

<ul class="stagger flex flex-col gap-3">
  <li class="animate-rise flex items-center justify-between">
    <span>Dana Whitfield</span>
    <span class="badge badge-neutral">Owner</span>
  </li>
  <li class="animate-rise flex items-center justify-between">
    <span>Priya Raman</span>
    <span class="badge badge-neutral">Admin</span>
  </li>
</ul>

State transitions

animate-collapse-in and animate-collapse-out animate height from zero using grid rows. transition-discrete lets display and overlay transition together on a popover or an [open] element. transition-size animates height: auto directly.

  <summary class="font-semibold">What happens when a run is cancelled?</summary>
  <div class="animate-collapse-in duration-fast">
    <p class="text-sm mt-3">Partial output stays for 24 hours, then is deleted.</p>
  </div>
</details>

<div class="popover-anchor popover-toggle">
  <div class="popover transition-discrete">
    <p class="text-sm">Opens and closes as one discrete transition.</p>
    <div class="popover-arrow"></div>
  </div>
  <button class="btn btn-outline btn-sm" aria-haspopup="true">Cluster status</button>
</div>

Scroll reveals

reveal, reveal-up and reveal-scale are pure CSS scroll-driven animations, played by animation-timeline: view() inside an @supports guard. Wherever that is missing the element renders plainly visible, never hidden. Scrolling back up replays a reveal in reverse; there is no pure CSS once-only.

<div class="grid grid-cols-1 md:grid-cols-2 gap-4">
  <div class="panel p-5 reveal-up">
    <h3 class="font-semibold">Progress linked</h3>
    <p class="text-sm">Stops the instant the reader stops scrolling.</p>
  </div>
  <div class="panel p-5 reveal-scale delay-150">
    <h3 class="font-semibold">Degrades to visible</h3>
    <p class="text-sm">No rule outside the support query hides this content.</p>
  </div>
</div>

View transitions

Six name-only helpers, vt-hero, vt-title, vt-media, vt-panel, vt-name and vt-none, hand the browser a view-transition-name. A name has to be unique per document per snapshot. The addon does not ship the @view-transition at-rule: it is document scoped, so shipping it would turn on cross-document transitions for every site that merely links the file.

Reduced motion

The core kill switch forces every animation to a 0.01ms duration for a reduced-motion user, and animation-fill-mode: both lands the element on its final frame: entrances appear, exits disappear, nothing travels. No addon rule leaves content hidden. The reveal family goes further and sits entirely inside prefers-reduced-motion: no-preference, so a reduced-motion reader never depends on the kill switch at all. Use motion-reduce:animate-fade-in in place of a slide or scale when a fade is the better fallback.

Components

Every component is MIT with its full HTML in the registry, so there is nothing to unlock and nothing to guess. Copy the markup from the gallery, write it to disk with the CLI, or fetch it as JSON.

npx llmcss list
npx llmcss search pricing
npx llmcss add btn-variants          # writes components/primitive/btn-variants.html

curl https://llmcss.io/registry.json
curl https://llmcss.io/r/btn-variants.json

Some components ship more than one layout. Ask for one by reference, component:variant, on any command that takes a component id.

npx llmcss variants hero-split
npx llmcss add hero-split:centered   # writes components/marketing/hero-split-centered.html

Categories are primitive, application, marketing and ecommerce. Full metadata for one id, plus its variant references: npx llmcss info <id>.

Runtime and states

Interactive components run on data-ai-toggle and data-ai-dismiss once llmcss.js is on the page, and the runtime handles focus trapping, Escape, and aria-expanded for you. The markup below renders and themes correctly without the script; only the opening and closing needs it.

<button class="btn btn-primary" data-ai-toggle="modal" data-ai-target="#demo-modal"
        aria-haspopup="dialog" aria-expanded="false">Open</button>

<div id="demo-modal" class="modal">
  <div class="modal-backdrop" data-ai-dismiss="modal"></div>
  <div class="modal-box" role="dialog" aria-modal="true" aria-labelledby="demo-modal-title">
    <div class="modal-header">
      <h3 class="modal-title" id="demo-modal-title">Confirm database reset</h3>
      <button class="modal-close" data-ai-dismiss="modal" aria-label="Close">&times;</button>
    </div>
    <div class="modal-body"><p>All mock records revert to initial seed.</p></div>
    <div class="modal-footer">
      <button class="btn btn-outline" data-ai-dismiss="modal">Cancel</button>
      <button class="btn btn-danger" data-ai-dismiss="modal">Reset</button>
    </div>
  </div>
</div>

State you write by hand is an is-* class from states.json plus the aria attribute that mirrors it. Write both: the runtime keeps them in sync after load, but it cannot fix the markup you shipped.

<button class="tab is-active" role="tab" aria-selected="true" data-ai-tab="#panel-a">Overview</button>
<a class="nav-link is-active" href="/docs" aria-current="page">Docs</a>
<button class="btn btn-primary is-loading" aria-busy="true">Saving</button>
<input class="input is-error" aria-invalid="true" />
<span class="status-pip is-streaming"></span><!-- the only state allowed to animate -->

Templates and recipes

Section templates are wireframe blocks for a header, hero, pricing table or footer, and page blueprints assemble a whole page in build order. Browse them in the template gallery or pull them from the CLI.

npx llmcss templates                              # every section template
npx llmcss template get wireframe-nav-minimal     # one section's HTML
npx llmcss template blueprints                    # full-page recipes
npx llmcss template blueprint saas-landing        # assemble the page

Themed templates and page kits are the Pro tier at $9 per month, unlocked with npx llmcss login <token>. Components are never Pro.

Validate and audit

validate checks every token in every class attribute against classes.json, warning on an unknown name and failing on an unknown is-* state or a stray ai- prefix. audit checks the same file against the anti-slop design laws, and both exit 1 on a finding so either one can fail a build.

npx llmcss validate index.html
npx llmcss validate --strict index.html   # unknown classes fail too
npx llmcss lint --fix index.html          # strips a stray ai- prefix in place
npx llmcss audit index.html

A clean file prints one line per command. A file with findings prints the line number, the category and the fix, then exits 1.

$ npx llmcss validate index.html

  ✦ Validating index.html for LLMCSS standards...

  Line 1: warning Unknown class "btn-primry". Use "btn-primary".
  Line 2: error Removed ai- prefix "ai-badge". Use "badge".

  ✗ 1 error, 1 warning. Run `npx llmcss lint --fix index.html` to migrate the renamed classes.

$ npx llmcss audit index.html

  ✦ LLMCSS Design Quality Audit: index.html

  Found 1 design quality issues:

  Line 0 [Cardocalypse]: 1 card is nested inside another card. Use whitespace, divider, or a surface shift instead.
    Fix: Flatten hierarchy: use whitespace or hairline rules instead of nesting cards.

CLI

The binary is llmcss, so npx runs it with nothing installed. Add it as a dev dependency with npm install --save-dev llmcss if you want it in a script.

npx llmcss list                    # every component id, all MIT
npx llmcss search <query>          # search by keyword, tag, or alias
npx llmcss info <id>               # raw component metadata
npx llmcss add <id>                # write component HTML into components/
npx llmcss validate <file>         # class-name gate, --strict to fail on warnings
npx llmcss lint --fix <file>       # strip a stray ai- prefix
npx llmcss audit <file>            # anti-slop design checks
npx llmcss harness <archetype>     # design tokens and prompt directives
npx llmcss templates               # list wireframe section templates
npx llmcss template blueprint <id> # assemble a full page
npx llmcss login <token>           # save a Pro license token

Legacy aliases cssai and cssai-mcp still resolve to the same binaries.

MCP server

llmcss-mcp is a stdio Model Context Protocol server that gives an agent the class list, the token list, the component markup and the validator as callable tools. It talks to the public catalog at llmcss.io, so there is nothing long-lived to host on your machine.

npx llmcss-mcp

Almost every client takes the same three fields. This is the generic form; the cards below give the exact file for each tool.

{
  "mcpServers": {
    "llmcss": {
      "command": "npx",
      "args": ["-y", "llmcss-mcp"]
    }
  }
}

Tools: search_components, get_component_markup, validate_markup, list_classes, list_tokens, list_states, llmcss_get_harness, llmcss_slop_audit, list_wireframe_templates, get_wireframe_template, get_page_blueprint, plus two compatibility aliases (cssai_get_harness, cssai_slop_audit).

Works with your agent

LLMCSS is an open-source CSS library whose class names, design tokens and state classes are published as machine-readable files, so a coding agent can look up what exists instead of inventing it. It ships llms.txt, llms-full.txt, classes.json, an MCP server (llmcss-mcp) and a CLI (llmcss), and it works with any agent that can read a Markdown file or connect to an MCP server. No plugin, no extension and no account is required for any of the setups below.

Claude Code

Reads AGENTS.md from the project root automatically, so the LLMCSS rules load with no configuration. Add the MCP server to look classes up from the CSS library live.

claude mcp add llmcss -- npx -y llmcss-mcp

Claude Desktop and Claude.ai

Add LLMCSS as a connector in claude_desktop_config.json and the CSS library's tools appear in every chat.

{
  "mcpServers": {
    "llmcss": { "command": "npx", "args": ["-y", "llmcss-mcp"] }
  }
}

Cursor

Put the LLMCSS server in .cursor/mcp.json and point a project rule at AGENTS.md so the CSS library's conventions are always in context.

// .cursor/mcp.json
{ "mcpServers": { "llmcss": { "command": "npx", "args": ["-y", "llmcss-mcp"] } } }

// .cursor/rules/llmcss.mdc
---
description: LLMCSS class and token rules
alwaysApply: true
---
Always follow AGENTS.md. Never invent a class outside classes.json.

GitHub Copilot in VS Code

Copilot agent mode reads .vscode/mcp.json, and repository instructions carry the LLMCSS rules into every completion from the CSS library.

// .vscode/mcp.json
{ "servers": { "llmcss": { "command": "npx", "args": ["-y", "llmcss-mcp"] } } }

// .github/copilot-instructions.md
Use LLMCSS classes only. The rules are in AGENTS.md.

OpenAI Codex CLI

Codex reads AGENTS.md natively, so the LLMCSS rules apply on the first run, and the CSS library's MCP server goes in the TOML config.

# ~/.codex/config.toml
[mcp_servers.llmcss]
command = "npx"
args = ["-y", "llmcss-mcp"]

Gemini CLI

Register the LLMCSS server in settings, then have GEMINI.md include AGENTS.md so the CSS library's rules travel with the project.

// ~/.gemini/settings.json
{ "mcpServers": { "llmcss": { "command": "npx", "args": ["-y", "llmcss-mcp"] } } }

// GEMINI.md
@AGENTS.md

Windsurf

Cascade loads MCP servers from mcp_config.json, which is all LLMCSS needs to expose the CSS library's class and token lookups.

// mcp_config.json (Windsurf MCP settings)
{ "mcpServers": { "llmcss": { "command": "npx", "args": ["-y", "llmcss-mcp"] } } }

Cline and Roo Code

Both keep MCP servers in a settings JSON file reachable from the MCP panel, and both take the LLMCSS entry unchanged for the CSS library's tools.

// cline_mcp_settings.json / mcp_settings.json
{ "mcpServers": { "llmcss": { "command": "npx", "args": ["-y", "llmcss-mcp"] } } }

Zed

Zed calls MCP servers context servers, and one entry in settings.json gives the agent panel the LLMCSS tools for the CSS library.

// ~/.config/zed/settings.json
{ "context_servers": { "llmcss": { "source": "custom", "command": { "path": "npx", "args": ["-y", "llmcss-mcp"] } } } }

Aider

Aider has no MCP client, so hand it the LLMCSS rules as a read-only file and the CSS library behaves the same way.

aider --read AGENTS.md

Continue

mcpServers:

OpenAI Agents SDK

Attach the LLMCSS server over stdio and your agent gets the CSS library's class lookup and validator as tools.

from agents import Agent
from agents.mcp import MCPServerStdio

async with MCPServerStdio(
    params={"command": "npx", "args": ["-y", "llmcss-mcp"]}
) as llmcss:
    agent = Agent(name="UI", instructions="Use LLMCSS classes only.",
                  mcp_servers=[llmcss])

Claude Agent SDK

Pass the LLMCSS server in the query options and the agent can validate its own markup against the CSS library before returning it.

import { query } from "@anthropic-ai/claude-agent-sdk";

for await (const msg of query({
  prompt: "Build a pricing page with LLMCSS.",
  options: { mcpServers: { llmcss: { command: "npx", args: ["-y", "llmcss-mcp"] } } }
})) console.log(msg);
